# AI Agent 开发规则

## 基本原则

1. 每次只实现一个明确功能。
2. 修改代码前，先说明计划修改哪些文件。
3. 不允许无关重构。
4. 不允许擅自改变项目定位。
5. 不允许把项目做成普通聊天机器人或论文总结器。
6. 保持项目始终可运行。

## 代码规则

1. 使用 TypeScript。
2. 核心数据结构必须有类型定义。
3. UI 组件和业务逻辑分离。
4. AI 调用统一经过 modules/llm/。
5. 本地存储统一经过 modules/storage/。
6. 学习状态统一经过 modules/state/。
7. 错误诊断逻辑统一放在 modules/diagnosis/。

## 依赖规则

项目基础技术栈是：

- Electron
- React
- Vite
- TypeScript

如需新增依赖，必须先说明：

1. 依赖名称；
2. 用途；
3. 为什么不用现有能力实现；
4. 可能带来的复杂度。

## 开发流程

每次任务完成后，必须说明：

1. 修改了哪些文件；
2. 新增了哪些功能；
3. 如何运行；
4. 如何测试；
5. 是否影响已有功能。

## Mock 优先原则

在真实 AI 接口或 PDF 解析未完成前，可以使用 mock 数据。

但要求：

1. mock 数据结构必须接近真实数据；
2. 后续可以平滑替换为真实 API；
3. 不允许把 mock 逻辑写死在 UI 组件中。

## 禁止一次性实现内容

以下内容不应在 MVP 阶段一次性实现：

1. 多篇论文对比；
2. 大规模领域知识库；
3. 自动爬取论文；
4. 复杂公式识别；
5. 高级图谱推理；
6. 完整用户账号系统。
